# 首页背景橡皮擦滚动失效：需求与任务文档

> 状态：已修复并通过回归验证  
> 分支：`feat/dual-audience-learning-loop`  
> 日期：2026-11-17  
> 影响范围：首页及其他使用 `BackgroundDecor` 的页面

## 1. 问题描述

首页背景切换到“橡皮擦揭示”后，只要页面内容产生纵向滚动条，并向下滚动到首屏之外，橡皮擦就会消失：覆盖层可以被擦开，但底下没有可揭示的涂鸦图案。

调整浏览器窗口尺寸后，橡皮擦效果会立即恢复。

## 2. 复现步骤

1. 打开首页。
2. 在左下角背景切换器中选择“橡皮擦揭示”。
3. 将页面滚动到下方。
4. 移动鼠标，确认橡皮擦覆盖层仍有擦除动作，但不再露出底层图案。
5. 轻微调整窗口宽度或高度，底层图案重新铺满页面，橡皮擦恢复。

自动化复现条件：

- 视口高度约 650px。
- 首页文档高度约 1800px。
- 背景模式必须在页面内容完成布局前持久化为 `reveal`，以复现真实用户刷新页面时的时序。

## 3. 预期行为

- 橡皮擦底层图案始终覆盖整个文档，包括所有可滚动区域。
- 页面内容高度增长、窗口尺寸变化或滚动位置变化后，都不应让底层图案缺失。
- 用户无需刷新或调整窗口尺寸即可在页面任意位置继续擦出涂鸦。
- 不影响“磁吸点阵”“纯点阵”模式及左下角背景切换器。

## 4. 根因

`components/interactiveBackground.tsx` 中存在两套不同的画布尺寸管理逻辑：

- **覆盖层画布**通过共享的 `useCanvas` 在每一帧同步 `document.documentElement.scrollHeight`，因此会覆盖整个滚动文档。
- **底层涂鸦画布**只在组件挂载和浏览器 `resize` 时重新计算尺寸并绘制。

当 `reveal` 模式在首页短暂加载态中挂载时，页面文档高度尚接近视口高度，底层画布因此只绘制了约 650px。首页数据加载完成后，文档增长到约 1800px，但底层画布没有同步重绘；覆盖层仍覆盖全页，因此下半页只能擦出一块空白。调整窗口尺寸会触发底层画布重绘，所以效果恢复。

浏览器采样结果：

| 状态 | 底层画布高度 | 覆盖层画布高度 | 文档高度 |
| --- | ---: | ---: | ---: |
| 首次挂载 | 650px | 650px | 650px |
| 内容加载后（故障） | 650px | 1797px | 1797px |
| 调整窗口尺寸后（恢复） | 1797px | 1797px | 1797px |

## 5. 技术要求

1. 底层涂鸦画布必须与覆盖层画布使用一致的文档高度口径。
2. 文档高度增长时，底层画布应自动调整尺寸并重新绘制图案。
3. 继续保留现有 10000px 画布高度上限和超长页面降低 DPR 的策略。
4. 避免为静态底层画布引入不必要的持续重绘；尺寸未变化时不应反复重建图案。
5. 清理方案验证期间加入的临时日志与临时复现脚本。

## 7. 验收标准

- 在约 650px 高视口、约 1800px 高的首页中，滚动到底部后，橡皮擦仍可露出非透明底层图案。
- 不调整窗口尺寸也能完成该操作。
- 底层与覆盖层画布的 CSS 高度均覆盖当前文档高度（并遵守 10000px 上限）。
- 页面内容动态变高后，底层画布无需刷新即可同步。
- 原有背景模式和背景偏好持久化行为不受影响。
- TypeScript 检查、diff 检查和生产构建通过。

## 8. 回归测试策略

该问题依赖真实浏览器中的布局时序、DOM 尺寸和 Canvas 像素，单元测试无法充分覆盖。回归测试应通过 Chrome DevTools Protocol 执行：

1. 启动独立测试服务。
2. 以固定视口打开首页。
3. 在页面脚本执行前持久化 `reveal` 模式并重新加载。
4. 等待首页内容完成布局。
5. 滚动到页面底部并移动鼠标。
6. 断言底层与覆盖层画布均覆盖文档高度。
7. 断言当前可见区域能采样到非透明底层图案。

该测试必须在修复前稳定失败、修复后稳定通过。

## 10. 修复说明

底层与覆盖层画布现在统一通过 `getDocumentCanvasSize()` 获取文档宽高，并统一使用 `resizeCanvas()` 处理 DPR、画布后备存储和 CSS 尺寸。底层画布额外通过 `ResizeObserver` 观察 `document.body` 的内容盒尺寸：首页数据异步加载或内容动态变高时自动重绘；尺寸未变化时不重复重建图案。
